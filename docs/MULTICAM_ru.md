# MultiCam: съёмка сцены INSIDE многими камерами сразу

MultiCam снимает один прогон сцены сразу с нескольких виртуальных камер. Все камеры видят одно и то же состояние игры на каждом шаге:

- неподвижные ракурсы;
- камеры, которые следуют за мальчиком, тюком или группой цыплят;
- пролёты по ключевым точкам;
- режиссёрская камера, которая плавно перелетает между планами прямо в игре.

Потом офлайн-инструменты собирают видео по каждой камере, раскладку в стиле Blender и смонтированный ролик с замедлением и размытием движения.

Подробное руководство на английском: [MULTICAM.md](MULTICAM.md). Записи и просмотрщик записей: [RECORD_REPLAY.md](RECORD_REPLAY.md). Захват звука и InsideMuter: [AUDIO.md](AUDIO.md). Лаборатория: [LAB.md](LAB.md). Сервер MCP: [MCP.md](MCP.md). Контракты для разработки: [MULTICAM_DESIGN.md](MULTICAM_DESIGN.md), [REPLAY_DESIGN.md](REPLAY_DESIGN.md).

Обозначения:

- `<game>`: папка INSIDE (где лежит `INSIDE.exe`);
- `C:/path/to/InsideDevTool`: папка этого репозитория или релиза;
- `<take>`: папка дубля, всегда полный путь.

Пути в командах `mcam` полные, прямые слэши подходят. Относительный путь считается от рабочей папки игры, а не от репозитория. Путь с пробелами взять в кавычки. Команды Python запускаются из папки репозитория.

## Как включить и выключить

- MultiCam входит в ядро InsideDev (`InsideDev.dll`). У него нет настройки, горячей клавиши или фоновой задачи: пока не пришла команда `mcam ...`, его код не работает и в игре ничего не меняется.
- Команды `mcam` мостовые, внутриигровая консоль редактора их не выполняет. Отправлять их можно:
  - MCP-инструментом `command` (`InsideDev.Mcp.dll`);
  - запросом `POST /cmd` на `http://127.0.0.1:47811` (та же DLL), например `python -I tools/inside_ctl.py mcam status`;
  - через файловый мост: файл `<game>\_mod\cmd\in_<любое>.txt` с текстом `<id>|<команда>`, ответ появится в `<game>\_mod\cmd\out.txt`.
- Команды запуска (`start`, `rehearse`, `preview`, `record`, `replay`, `take`, `passes`, `golden`) открывают сессию съёмки. Она запоминает и в конце возвращает: скорость времени, vsync, разрешение, оверлеи редактора, свободную камеру, параметры игровой камеры, TAA и пост-эффекты, интерполяцию тел, удержание подсцен. Одновременно идёт только один запуск.
- Остановить: `mcam stop` (доснять текущий шаг, записать файлы, всё вернуть) или `mcam abort` (вернуть всё сразу, даже если раннер упал; сначала останавливает захват звука). Ход съёмки показывает `mcam status`.
- Блокировка на время съёмки (`session.lockInput`, по умолчанию включена): горячие клавиши и мышь редактора выключены, чужие команды получают ответ `busy: mcam capturing`. Пропускаются только `mcam status|stop|abort|check|list|pose|schema|help`, `srec status|objects|event`, `acap status`, `state`, `game_state`, `ping` и `audio`.
- Не откатывается: команды из `setup` и `cues` (`god on` остаётся включённым, загруженный `load` уровень остаётся, правила звука остаются). После режимов повтора (`record`, `replay`, `take`, `passes`, `golden`) игра заморожена на последнем кадре, пока не дать `ts 1`, не загрузить уровень или не запустить следующий `mcam`.
- `mcam show <cam>` ставит свободную камеру в позицию камеры спецификации; `cam off` возвращает игровую камеру. `clean on|off`, `hud on|off`, `gamma <0..1>` / `gamma reset` не пишут в `editor.cfg`.

## Что нужно

- `bin\InsideDev.dll` в `<game>\_mod\` (как в README).
- По желанию `bin\InsideDev.Mcp.dll` в `<game>\_mod\`: MCP-инструмент `command` и `POST /cmd` (нужен для `tools/mcam_previews.py`).
- По желанию `bin\InsideReadback.dll`: копировать в `<game>\INSIDE_Data\Plugins\`, пока игра закрыта. Это асинхронное чтение кадров для проходов повтора с `output.format: "pipe"` и для эталонных кадров. При `output.readback: "auto"` (по умолчанию) без плагина используется ReadPixels; проверка: `mcam readback test`, затем `mcam readback status`.
- ffmpeg. В игре `output.ffmpeg` по умолчанию `"ffmpeg"`: ищется в PATH процесса игры, можно указать полный путь. Инструментам ffmpeg и ffprobe берутся из переменных окружения `FFMPEG` / `FFPROBE` или из PATH. Нужны `hevc_nvenc` (видеокарта NVIDIA) и `zscale`.
- Python 3 с пакетами numpy, opencv-python, Pillow, numba, matplotlib.
- Шрифт подписей `tools\fonts\Oswald-Regular.ttf` в релиз не входит: компоновщик берёт Bahnschrift из Windows или файл шрифта из `compose.labels.font`.

## Как это работает

Настоящая камера в игре одна: копия `_Camera_Main` сама себя удаляет. Поэтому MultiCam двигает эту камеру. На каждом шаге:

1. Один кадр игры идёт с фиксированной частотой: физика, анимации, игровая камера.
2. Время замораживается.
3. Камера по очереди встаёт в позицию каждой виртуальной камеры. Делает 1 кадр прогрева и N кадров сглаживания (TAA), потом сохраняет картинку.
4. Игровая камера возвращается на место, и идёт следующий шаг.

Замедление означает больше шагов на секунду игры. Размытие движения: несколько шагов, усреднённых в один кадр.

## Порядок работы

Пример: `specs/template_minimal.json` (игровая камера и один неподвижный ракурс там, где игра уже находится, 5 секунд).

1. **Проверка спецификации без игры.** Ошибки, предупреждения, таблица скоростей, стоимость съёмки, размеры раскладки, длины планов монтажа:
   `python -I tools/mcam_spec_check.py specs/template_minimal.json`
2. **Ракурс.** Облететь сцену свободной камерой, потом `cam json wide` выдаст готовый объект камеры для спецификации.
3. **Проверка в игре.** Какие объекты нашлись (`путь #id активен позиция`), события, сегменты:
   `mcam check C:/path/to/InsideDevTool/specs/template_minimal.json`
4. **Кадрирование.** По одному кадру с каждой камеры:
   `mcam preview C:/path/to/InsideDevTool/specs/template_minimal.json <take>`
   Лист с кадрами: `python -I tools/mcam_qa.py sheet <take>`.
5. **Репетиция** (для событий с отрицательным сдвигом). Полный тайминг и события, но без картинок, поэтому быстро:
   `mcam rehearse <spec> <take_rehearsal>`
   Путь к папке репетиции вписать в ключ `rehearsal` спецификации и удалить значения `expect`: они важнее репетиции. `seed` не менять.
6. **Съёмка:** `mcam start C:/path/to/InsideDevTool/specs/template_minimal.json <take>`. Ход съёмки показывает `mcam status`.
7. **Видео и проверка:** `python -I tools/mcam_compose.py all <take>`, затем `python -I tools/mcam_qa.py qa <take>`. Результат пишется в `C:/path/to/InsideDevTool/out/<имя спецификации>/`; другая папка через `--out` внутри `out/`, вне её только с `--force`.

## Команды

| Команда | Что делает |
|---|---|
| `mcam check <spec> [json] [replay\|v2]` | загрузка, проверка, отчёт по объектам и событиям |
| `mcam start <spec> <out>` | съёмка дубля |
| `mcam rehearse <spec> <out>` | тайминг и события без картинок |
| `mcam preview <spec> <out> [t]` | по кадру с каждой камеры сейчас или на секунде `t` дубля |
| `mcam stop` / `mcam abort` | закончить шаг и всё вернуть / вернуть всё сразу |
| `mcam status [json]` | ход съёмки |
| `mcam show <cam> [t]` / `mcam pose <cam> [t]` | поставить свободную камеру в позицию камеры / напечатать позицию |
| `mcam probe <obj>` | сигналы, FSM и триггеры объекта с готовыми заготовками событий |
| `cam pose x y z yaw pitch [fov] [сек] [roll]` | плавно перевести свободную камеру |
| `cam json [имя]` | текущая позиция как объект камеры |
| `cam off` | назад к игровой камере |
| `ts 1` | снять заморозку после режима повтора |

Только в `setup`:

- `wait <сек>`;
- `waitfor loaded`;
- `waitfor streaming`;
- `waitfor savepoint <имя>` (номера как в `load 7 0` или часть подписи из `game_state`, например `#chickenGun`);
- `waitfor event <имя>`.

Каждый `waitfor` через 60 секунд реального времени прерывает запуск с ошибкой.

## Звук

MultiCam никогда не глушит игру: во время дубля звук играет как при обычной игре. Чтобы игра молчала во время дубля, добавить в начало `setup` (до любого `load`):

```json
"audio force rtpc rtpc_master_volume 0", "audio native on"
```

Первая строка: правило звука, громкость Wwise всегда 0, пока правило не снято или игра не закрыта. Вторая дублирует правила в загрузчике (`version.dll` v3); эта настройка запоминается в `<game>\_mod\editor.cfg`. Снять после съёмки: `audio clear rtpc:rtpc_master_volume` (вернётся громкость, которую сама игра ставила в этой сессии). Если игра так и молчит, сначала задать её громкость (`audio force rtpc rtpc_master_volume <0-100>`), потом снять правило ([RECORD_REPLAY.md](RECORD_REPLAY.md), раздел 8.7). Дубль в загрузчике выключается командой `audio native off`. Команды `audio` проходят блокировку съёмки.

## Главное о формате

- **Версия.** Всегда писать `"version": 2`. Без неё действуют старые умолчания v1: fov 40 (кроме камер `game` и `director`), settle 3, JPEG 92, а цели `boy` и `huddle` берут точку `pos3`.
- **Комментарии.** Ключи, которые начинаются с `_`, и ключ `comment` игнорируются. В них удобно писать заметки.
- **Время.** Секунды игры от t=0 или время от события: `"@baleFall+0.3"`, `"@baleFall-0.5"`.
  - Отрицательному сдвигу нужен прогноз: `expect` у события или папка `rehearsal`.
- **Углы.** Углы Unity: yaw 0 смотрит в сцену (+Z), положительный pitch смотрит **вниз**.
- **FOV.** Вертикальный FOV; 0 значит игровой (50,99).
- **Правило стороны игрока.** Камеры только перед декорацией (z меньше -2) или сверху. Никогда за ней и никогда не смотреть назад, в сторону экрана: у декораций нет задней стороны.
- **Команды `setup`** меняют игру и после дубля не откатываются.
- **Режимы камер:**
  - `game`: игровая камера;
  - `static`: неподвижная камера;
  - `follow`: следует за объектом;
  - `keys`: пролёт по ключам;
  - `rail`: равномерный проезд по точкам;
  - `orbit`: дуга вокруг объекта;
  - `gamerel`: другой ракурс игрового плана;
  - `gamelike`: игровая логика слежения для любого объекта;
  - `frame`: держит объект в точке кадра;
  - `director`: монтаж в игре;
  - `overview`: общий план на постоянной высоте, едет по x за действием;
  - `events`: переходит от объекта к объекту по событиям.

### Замедление и размытие

`speed`: секунды игры на секунду видео, 0,25 значит замедление в 4 раза. `samples`: сколько подшагов усреднить в кадр. `shutter`: угол затвора.

Частота шагов R = round(samples × 360 / shutter) × fps / speed. Она должна быть целой, от 10 до 960, и делить 60 или делиться на 60.

| Что нужно (fps 30) | speed | samples | shutter | R |
|---|---|---|---|---|
| обычная скорость, без размытия | 1 | 1 | нет | 30 |
| обычная скорость, мягкое размытие | 1 | 4 | 180 | 240 |
| замедление ×2 | 0.5 | 2 | 180 | 240 |
| замедление ×4 | 0.25 | 2 | 180 | 480 |
| замедление ×8 | 0.125 | 2 | 180 | 960 |

Лучше брать точные скорости: 1, 0.5, 0.25, 0.125.

### Свет

Сцены тёмные, поэтому тени поднимаем мягко и блеклую картинку не делаем.

- В игре: `brightness` 0,55-0,60, `blacklift` не больше 0,025 в сумме, `postGamma` 0,03-0,08.
- Офлайн: подъём с якорем на чёрном (`compose.grade`).
- Два сильных подъёма сразу не складывать.

## Полный пример

Дубль ChickenGun в реальном времени: игровая камера, три проверенных ракурса, камера за тюком, раскладка и монтаж из трёх планов по 4-5,5 с. Такого файла в релизе нет, текст можно скопировать в свою спецификацию.

```json
{
  "version": 2,
  "name": "chickengun_example",
  "seconds": 14,
  "seed": 1,
  "setup": [
    "god on", "panel off", "triggers off", "labels off", "savepoints off",
    "load 7 0", "waitfor savepoint #chickenGun", "waitfor streaming", "wait 3",
    "tp 221.0 -221.4 0.66", "wait 2",
    "call ChickenGunObject/ChickenGunVacuumLogic ChickenGunLogic OnElectricityOn",
    "call _SaveLogic/ChickensLoaded ChickenSpawner DoSpawn", "wait 1"
  ],
  "cues": [[1.0, "call ChickenGunObject/ChickenGunVacuumLogic ChickenGunLogic ToggleSuctionOn"]],
  "timing": {"fps": 30},
  "render": {"warmup": 1, "samples": 8},
  "post": {"brightness": 0.55, "blacklift": 0.006, "postGamma": 0.03},
  "cameras": [
    {"name": "game", "mode": "game"},
    {"name": "low_left", "mode": "static", "pos": [215.5, -220.3, -6.5], "yaw": 30, "pitch": -12, "fov": 50},
    {"name": "outlet_bale", "mode": "static", "pos": [225.0, -219.0, -6.0], "yaw": 20, "pitch": -18, "fov": 45},
    {"name": "high", "mode": "static", "pos": [222.0, -213.0, -11.0], "yaw": 10, "pitch": 25, "fov": 50},
    {"name": "bale", "mode": "follow", "target": {"of": "HayBaleHolder/HayBale", "point": "bounds"},
     "offset": [-2.4, 0.3, -7.2], "lookOffset": [0.4, 0, 0], "fov": 42, "smooth": 0.5, "lookSmooth": 0.15}
  ],
  "compose": {
    "layouts": [{"name": "main", "width": 2560, "gap": 4, "rows": [
      [{"cam": "game", "crop": [0, 180, 2560, 1080]}],
      [{"cam": "low_left"}, {"cam": "outlet_bale"}, {"cam": "bale"}]
    ]}],
    "edit": {"name": "cut1", "fadeIn": 0.5, "fadeOut": 1.0, "minHold": 4, "maxHold": 6, "shots": [
      {"cam": "game", "from": 0},
      {"cam": "outlet_bale", "from": 4.0, "in": {"type": "dissolve", "dur": 1.0}},
      {"cam": "bale", "from": 8.5, "in": {"type": "dissolve", "dur": 1.0}}
    ]}
  }
}
```

Раскладка `main` даёт кадр 2560×1564:

- сверху полоса 2560×1080 из игровой камеры;
- снизу три ячейки 851/851/850 × 480;
- между ними чёрные зазоры по 4 px.

Примеры в релизе:

- `specs/template_minimal.json`: игровая камера и один неподвижный ракурс там, где игра уже находится, 5 с;
- `specs/replay_smoke.json`: режим повтора, 10 с ChickenGun, две камеры, без звука, с эталонными кадрами.

## Режим повтора (replay)

Сцена один раз проигрывается в реальном времени и записывается. Потом игра замирает, и каждая камера снимается своим непрерывным проходом: мод сам выставляет сцену по записи. Подробно: раздел 18 в [MULTICAM.md](MULTICAM.md), дизайн: [REPLAY_DESIGN.md](REPLAY_DESIGN.md).

Что это даёт:

- все камеры видят один и тот же момент, окно не мигает между ракурсами;
- замедление с любой дробной скоростью (0.2, 0.35): промежуточные кадры интерполируются между записанными;
- размытие движения: родное размытие движка;
- новые камеры можно снять потом из той же записи (`replay.source`);
- примерно один рендер на кадр и камеру: семь камер ChickenGun снимаются за несколько минут вместо 40-65 минут v2.

Порядок работы (пример `specs/replay_smoke.json`, пути в командах `mcam` полные):

1. `python -I tools/mcam_spec_check.py specs/replay_smoke.json`
2. `mcam check C:/path/to/InsideDevTool/specs/replay_smoke.json`: спецификация с блоком `replay` сама проверяется по правилам повтора.
3. `mcam record <spec> <take>`: проход записи, папка `<take>/record`. Или сразу `mcam take <spec> <take>`: запись и повтор за одну сессию. После записи (и после `replay`, `take`, `golden`, `passes`) игра остаётся замороженной на последнем кадре, пока не дать `ts 1` (или другое значение), не загрузить уровень или не запустить следующий `mcam`.
4. Первый раз в сцене: эталонная проверка. В спецификации `record.captureGame: true` (в `replay_smoke.json` уже включено), затем `mcam golden <spec> <take>` и `python -I tools/mcam_qa.py replaydiff <take> --record <take>/record`: сверка повтора с кадрами записи (результат в `<take>/replaydiff/`; контур по краям проверяется только для верёвки, для остальных целей только выводится). С плагином InsideReadback кадры записи идут через асинхронное чтение и ffmpeg, без него каждый захват тормозит запись примерно на 34 мс; в любом случае это эталон, а не запись для дубля.
5. `mcam passes <spec> <take>`: план без кадров: время событий из записи, рендеры, диск.
6. `mcam replay <spec> <take>`: проходы камер; `cams=a,b` и `range=t0:t1` для черновика.
7. `python -I tools/mcam_compose.py all <take>`: видео каждой камеры (режиссёрской тоже) и раскладки, кодек hevc_nvenc Main10 (x265 только по запросу, `--codec x265`, он во много раз медленнее). `all` собирает монтаж только из явного `compose.edit` и никогда не строит автомонтаж.
8. `python -I tools/mcam_qa.py qa <take>`

Ограничения:

- **Замороженные эффекты `_Time`.** Шейдеры, которые анимирует встроенное время Unity, в повторе стоят на месте. В ChickenGun это полосы дождя, рябь в грязи, края брызг и жёлоб с зерном (мотыльки частично), у озера: дождь и поверхность воды. Подменить `_Time` нельзя: движок ставит его для каждой камеры сам. Поэтому ключ `replay.play.unityTime` убран, и проверка выдаёт на него ошибку. План, которому нужны эти эффекты, снимать обычным v2 (`mcam start`).
- Также не повторяются симуляция воды в текстурах, волосы (Hair), обычные LineRenderer и процедурные меши. Канат крана повторяется.
- Блики линз, свет CameraLightSwap, край воды и аудиозонд камеры работают вживую для каждой камеры.
- Камеры повтора: предупреждение, если камера смотрит дальше чем на 65° от +z. Вид сверху (наклон больше 60°) можно, если кадр показал, что пол на месте, и камера вписана в `replay.play.coverageOk`.

Звук в режиме повтора:

- Звук попадает в дубль только из прохода записи: `replay.audio.capture: "record"` (по умолчанию `"none"`, без звука). Проходы камер идут при замороженной игре и звук не пишут.
- Вывод захвата задаёт `acap output audible|muted` (хранится в `<game>\_mod\editor.cfg`, по умолчанию `audible`):
  - `audible`: звук игры слышен как обычно, окно захвата открывается сразу на уровне min(`audio.level`, громкость игры), громкость выше игровой не поднимается; глушитель и файлы-флаги не нужны;
  - `muted` (по выбору, если игра должна молчать): глушитель `tools\muter\InsideMuter.exe` со свежим heartbeat (`replay.audio.heartbeat`, по умолчанию `_mod/muter/heartbeat.json` от папки игры), громкость 0 вне окна захвата, и файл-флаг пройденного лабораторного этапа ([LAB.md](LAB.md)).
- `acap preflight` отвечает, начнётся ли захват, или называет причину отказа.
- После записи: `python -I tools/mcam_audio.py align <take>/record`, затем `python -I tools/mcam_audio.py track <take>`, затем `python -I tools/mcam_compose.py all <take> --audio record` (звук AAC в MP4, видео H.265). У всех камер один и тот же звук.

## Подводные камни

- **Свёрнутое окно игры ставит игру на паузу.** Ничего не рисуется, команды моста и MCP не отвечают, съёмка стоит, пока окно не развернуть (в `<game>\_mod\insidedev.log` строка `application paused`). Окно можно держать за другими окнами, но не сворачивать.
- **Гонка загрузки.** `load` асинхронный, а игра может стоять на уровне, с которого стартовала. После каждого `load` нужны `waitfor savepoint <нужная точка>` и `waitfor streaming`, иначе дубль начнётся на старом уровне или посреди загрузки. Если игру ведёте сами (MCP, `srec record`), дождитесь, пока `game_state` покажет нужную точку сохранения.
- **Возврат MCP через 600 с.** Если 600 секунд нет ни одного вызова (EditorState `mcp.idle_restore_s`, 0 = никогда), сервер возвращает всё, что меняли инструменты MCP: отпускает ввод агента, останавливает запись и проигрывание дорожки ввода, выключает пошаговый режим. Запуск `mcam` он не отменяет, но дубль, который ведёт агент через MCP, потеряет управление. Вызовом считаются инструменты MCP и `POST /cmd` (хватит `mcam status`), команды файлового моста не считаются. Подробно: [MCP.md](MCP.md), раздел 9.
- **Пошаговый режим.** Инструменты play MCP с первого вызова, который двигает игру, замораживают её между вызовами ([PLAY.md](PLAY.md), раздел 4.1). Запуск `mcam` на время сессии забирает часы себе. Ручная запись `srec record` часы не забирает: для записи в реальном времени сначала включите реальное время (`time {op:"realtime"}`).
- **Запись мешает запуску.** Пока загружен просмотрщик записи или идёт ручная запись, любой запуск `mcam` отказывает: сначала `srec end` или `srec record stop`.

## Частые ошибки

| Сообщение или симптом | Что сделать |
|---|---|
| `unknown key, ignored (did you mean 'lookSmooth'?)` | опечатка в имени ключа; регистр важен |
| `no "version": 2 but v2 keys` | добавить `"version": 2` |
| `step rate R = ... is not whole` | взять скорость и число подшагов из таблицы выше |
| `'@x-1' needs a prediction` | добавить `expect` событию или папку `rehearsal` |
| `static z ... is behind the player-side line` | камера за декорацией: z должен быть меньше -2 |
| `looks back toward the screen` | камера смотрит назад: уменьшить yaw или развернуть её на сцену |
| `tp needs exactly three numbers` | `tp x y z`: ровно три числа |
| `runs right after 'load'` | после `load` добавить `waitfor savepoint <имя>` и `waitfor streaming` |
| `unknown camera '...'` в compose | имя камеры в раскладке или монтаже не совпадает со списком `cameras` |
| `replay.play.unityTime: removed in revision 3` | удалить ключ: `_Time` подменить нельзя |
| `not allowed in a replay spec: give speed instead` | в режиме повтора нет `rate`, `rates` и `settle`: задавать `speed`, любую дробную |
| `audio capture refused by preflight: ...` | причину покажет `acap preflight`; для вывода `muted` нужны глушитель, свежий heartbeat и файл-флаг |
| `camera '...' is disabled` | у выключенной камеры (`enabled: false`) нет кадров; её нельзя ставить в раскладку |
| `busy: mcam capturing` | идёт съёмка: ждать (`mcam status`) или `mcam stop` / `mcam abort` |
| `the previous capture session was not restored` | прошлая сессия не закрыта: `mcam abort` |
| `output.ffmpeg: not found` | ffmpeg нет в PATH игры: добавить его папку в PATH до запуска игры или указать полный путь в `output.ffmpeg` |
| `output ... is outside ...; pass --force` | компоновщик и QA пишут в `out/` репозитория: выбрать папку там или добавить `--force` |
| игра слышна во время дубля | так и задумано; чтобы она молчала, см. раздел «Звук» |
| игра стоит после дубля повтора | `ts 1` |
| в кадре надписи редактора | `session.clean` оставить true, в `setup` выключить панель, триггеры, подписи |
| в кадре виден призрак прошлой камеры | `render.taa: "reset"`, `warmup` 1, `samples` от 4 |
| камера показывает игровой вид (флаг F) | объект не найден: смотреть отчёт `mcam check` и исправить путь |
| замедление начинается поздно | у отрицательного сдвига нет прогноза: репетиция и ключ `rehearsal` |
